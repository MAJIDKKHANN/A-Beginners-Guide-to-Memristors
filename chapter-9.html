Chapter 9 · Hands on

Build One in LTspice

Everything so far has been pictures. Now you build a memristor yourself, in free circuit software, and watch the bow tie from Chapter 4 appear on your own screen.

What you need

  • LTspice, a free circuit simulator from Analog Devices. It runs on Windows and Mac.
  • The two files below. Each is a short text file called a netlist: a list of parts and how they connect.
  • About fifteen minutes.

reram_basic.cirreram_variability.cir

Model?

LTspice has resistors and capacitors built in, but no memristor. So we describe one ourselves. A description of how a part behaves is called a model.

The plan: two parts and a rule

This is the sliding door from Chapter 1 turned into a recipe. The state s is how open the door is, from 0 (closed) to 1 (open). The device part uses s to decide its resistance. The rule decides how s changes.

Why a capacitor?

A capacitor keeps its voltage when no current flows into it. That is exactly the “remembers with the power off” behaviour we want. We use a 1 farad capacitor so that the current we push into it is simply how fast s changes.

The whole netlist

Here is reram_basic.cir. Lines starting with * are comments for humans. LTspice ignores them.

* A Beginner's Guide to Memristors, Chapter 9
* A simple bipolar ReRAM model and a test circuit.
* Open this file in LTspice and press Run.

* ---------- the memristor model ----------
* Pins: p (plus), n (minus), s (state, for plotting)
* s = 0 means door closed (HRS), s = 1 means door open (LRS)
.subckt reram p n s params: Ron=1k Roff=100k Von=1 Voff=-1 kon=20k koff=20k
* 1) The device: current = voltage / resistance, and resistance depends on s
Bmem p n I=V(p,n)/({Ron}*V(s)+{Roff}*(1-V(s)))
* 2) The memory: a 1 F capacitor holds the state as a voltage
Cs s 0 1
Rs s 0 1e12
* 3) The rule: open above Von, close below Voff, do nothing in between
Bs 0 s I={kon}*max(V(p,n)-{Von},0)*(1-V(s)) - {koff}*max({Voff}-V(p,n),0)*V(s)
.ends reram

* ---------- the test circuit ----------
* Sweep: 0 V up to +2 V, down to -2 V, back to 0 V
V1 in 0 PWL(0 0 1m 2 2m -2 3m 0)
X1 in 0 s reram
.ic V(s)=0
.tran 0 4m 0 1u
.end

Line by line

.subckt reram p n s params: ...
Starts our model, a subcircuit called reram. It has two normal pins, p and n, plus a pin s so we can watch the state. The params are the knobs: resistances and switching voltages.
Bmem p n I=V(p,n)/(...)
The device. A B source is a part whose current you write as a formula. Here: current = voltage ÷ resistance. The resistance blends from Roff (closed) to Ron (open) as s goes from 0 to 1.
Cs s 0 1
The memory: a 1 F capacitor. Its voltage is the state s.
Rs s 0 1e12
A huge resistor, just so the simulator is happy. It is so big that the state would take tens of thousands of years to leak away.
Bs 0 s I=...
The rule. The first half pushes s up only when the voltage is above Von. The second half pulls it down only when the voltage is below Voff. Between them, both halves are zero, so nothing changes.
(1-V(s)) and V(s)
These slow the door down as it nears fully open or fully closed, so s always stays between 0 and 1.
V1 in 0 PWL(...)
The test signal: a voltage that goes 0 V, up to +2 V, down to −2 V, and back to 0 V, over 3 milliseconds.
X1 in 0 s reram
Places one memristor between the signal and ground.
.ic V(s)=0
Starts the memristor closed (high resistance).
.tran 0 4m 0 1u
Simulate 4 milliseconds, in steps no bigger than 1 microsecond.

Run it

  1. Open LTspice, choose File → Open, set the file type to netlists (.cir) and open reram_basic.cir.
  2. Press Run (the running-man button). An empty plot window appears.
  3. Right-click the plot, choose Add Traces, and add V(s). That is the door position over time.
  4. Add a second trace and type -I(V1). That is the current through the memristor. The minus sign is there because LTspice counts current flowing out of a voltage source as negative.
  5. For the bow tie: right-click the horizontal axis label and change Quantity Plotted from time to V(in). Make sure it says V(in), not V(s). The x axis must be the voltage you apply, not the door position.

What you should see

Two paths, crossing at zero: the pinched loop. When the door is closed, the line is almost flat. When it is open, the line is steep. The jumps between them are SET and RESET.

Now play

Change one knob at a time in the .subckt line and run again:

Von=0.5 makes it switch earlier.

kon=2k makes it slow, so the door only half opens.

Roff=10k makes the closed door leak more current.

Adding variability

Remember Chapter 8: no two real memristors are identical. The second file, reram_variability.cir, simulates ten of them. The only change is this line:

X1 in 0 s reram Ron={mc(1k,0.2)} Roff={mc(100k,0.3)} Von={mc(1,0.1)} Voff={mc(-1,0.1)}
.step param run 1 10 1

mc(1k,0.2) means “a random value around 1 kΩ, up to 20% either way”. .step runs the simulation ten times, and each run picks new random values. Every loop comes out a little different, just like real devices.

Mistakes I made, so you do not have to

My first attempt at this model looked reasonable but never actually switched. These were the reasons:

  • The state was part of the circuit. I connected the memory capacitor into the main current path, so s just followed the input voltage. Keep the state on its own separate node.
  • The state could get stuck. I used a window formula that equals zero at s = 0. Starting at zero, the state could never move. Check your formula at both ends.
  • Nothing was remembered at 0 V. A real memristor holds its state with no voltage applied. If yours drifts back when the input returns to zero, it is not a memristor yet.
  • Sign confusion. I(V1) is negative when the source is pushing current out. Use -I(V1).

Going further

Our model is a behavioural model: it copies what a memristor does, not the physics of why. That is perfect for learning and for trying out circuit ideas. Research uses models that are fitted to measured devices. A good next step is the Yakopcic model: ready-to-use LTspice versions of it, and of several other well-known models, are in the free memristor-models-4-all collection on GitHub.

What we learned

  • LTspice has no memristor, so we write a model as a subcircuit.
  • A model needs a device part, a memory (the state), and a rule for changing it.
  • A 1 F capacitor on its own node makes a perfect state variable.
  • Thresholds make it non-volatile: between Voff and Von, nothing changes.
  • mc() and .step add variability, just like real devices.

You made it to the end. You now know what a memristor is, what is inside it, how it switches, how to read its famous curve, three big things it is used for, and how to build one in a simulator. The word list is there whenever you need a reminder.
